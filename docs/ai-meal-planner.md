# 경로 기반 AI 식사 추천

경로 검색 후 식사 시점·업종·방송·메뉴·메뉴 가격을 자연어로 입력하면 최대 3곳을 추천한다. 후속 입력은 이전 검색 조건을 전달해 수정하며 지도와 추천 카드가 함께 바뀐다. 전체 경로 목록, 상세·영상·저장 기능으로 돌아갈 수 있다.

## 실행 설정

백엔드 환경변수에 `DEEPSEEK_API_KEY`를 설정한다. `DEEPSEEK_MODEL` 기본값은 `deepseek-flash`다. 기존 카카오 API 키와 DB/CORS 설정도 필요하다. 키를 프론트엔드의 `NEXT_PUBLIC_*` 변수나 소스에 넣지 않는다.

PowerShell 예시:

```powershell
$env:DEEPSEEK_API_KEY = "<본인 키>"
$env:DEEPSEEK_MODEL = "deepseek-flash"
.\.venv\Scripts\python.exe -m uvicorn app.api.main:app --host 127.0.0.1 --port 8000
```

`backend/.env.example`은 설정 항목 참고용이다. 서버는 `.env` 파일을 자동으로 읽지 않으므로 셸 또는 Railway의 Variables에서 환경변수를 설정한다. 배포 시 백엔드와 프론트엔드를 모두 갱신한다. 서버 시작 시 기존 `init_db`가 새 `meal_route_contexts` 테이블을 생성한다.

## 처리 방식

1. 기존 경로 API가 서버에서 계산한 맛집 후보와 전체 수집 메뉴를 DB에 30분 동안 보관하고 임의 토큰 `meal_context_id`를 반환한다. 만료 데이터는 다음 경로 검색에서 삭제한다.
2. `POST /api/meal-recommendations`는 토큰·사용자 입력·이전 조건을 받는다. 브라우저가 보낸 식당/가격/경로 데이터는 받지 않는다.
3. DeepSeek Chat Completions JSON Output으로 검색 조건을 추출한다. 모델에는 사용자 입력·이전 조건·선택 가능한 업종/방송명만 보내며 좌표·전체 식당 데이터는 보내지 않는다. JSON 응답은 Pydantic으로 검증한다.
4. Python이 업종·방송·메뉴·예산·시간 범위를 검사하고 순위를 계산한다. 검증된 필드로 추천 이유를 작성한다. AI가 식당명이나 가격을 생성하지 않으며 SQL을 실행하지도 않는다.

공식 API 참고: [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/). 비사고 모드(`thinking: disabled`)와 JSON Output을 사용한다. 추가 AI SDK 의존성은 없다.

## 추천 기준

- 시간은 원래 경로상 통과 시점이며 실제 우회·도착 시간이 아니다. ‘한 시간쯤’ 기본 범위는 전후 30분이고 화면에서 해석된 조건을 확인할 수 있다.
- 가격은 메뉴 한 개 기준이며 일행 전체/1인 식사 총액을 보장하지 않는다. 가격이 없거나 0 이하인 메뉴는 예산 조건을 충족하지 않는다.
- 메뉴명과 예산은 같은 메뉴에서 충족해야 한다. 카드에 표시되는 대표 메뉴 3개 외에 전체 수집 메뉴도 검색한다.
- 메뉴를 지정하지 않은 식사 추천에서는 이름으로 확인 가능한 공기밥·사리 추가·주류·탄산음료 등을 가격 근거에서 제외한다. 모든 메뉴의 구성과 인분 수까지 판별하는 것은 아니다.
- 방송·업종은 정확 일치, 메뉴명은 공백을 무시한 부분 일치다. 같은 종류의 조건끼리는 OR, 다른 종류끼리는 AND다.
- 조건에 맞는 후보가 없으면 빈 결과를 반환하며 조건을 몰래 완화하지 않는다.
- 주차·영업 중·분위기·알레르기·실제 우회 등 확인할 수 없는 요청은 미확인 조건으로 표시한다. 제외 메뉴는 문자 검색이며 재료/알레르기 안전을 보장하지 않는다.
- 후속 요청은 전체 대화 원문 대신 직전의 구조화 조건을 사용한다. 새 경로/처음부터 버튼으로 초기화한다. 새로고침에는 AI 조건을 복원하지 않는다.

## 오류와 호출량

키 미설정 503, 잘못되거나 중단된 모델 응답 502, 시간 초과 504, 요청 과다 429, 경로 만료 410을 구분한다. 브라우저는 요청 취소와 45초 대기 제한을 적용하고 실패 시 직전 성공 결과를 유지한다.

동시 AI 호출은 프로세스당 4개, 경로 토큰당 20회로 제한한다. 토큰별 사용 횟수는 DB에서 원자적으로 증가시킨다. 이는 계정별/일별 지출 한도가 아니며 새 경로 검색으로 토큰을 새로 받을 수 있다. 공개 운영 시 필요 트래픽에 맞춰 제공자 지출 한도와 게이트웨이 제한을 설정한다.


시연 흐름: 경로 검색 → ‘한 시간쯤 뒤, 한식으로 2만 원 이하’ → 근거와 적용 조건 확인 → ‘30분 더 일찍’ → 지도/추천 변경 → 상세 영상 또는 저장.

자동 테스트에서는 DeepSeek 응답을 대역으로 검증한다. 실제 한국어 해석 품질과 외부 API 연결은 본인 키로 별도 확인해야 한다.
