## 해결하고자 한 문제

- 장거리 이동이나 나들이 때 "가는 길에 뭐 먹지"는 매번 반복되는 고민이다. 지도 앱은 현재 위치 기준 검색만, 방송 맛집 사이트는 지역별 목록만 제공해서 **경로와 시간을 함께 놓고 고르는 도구**가 없었다.
- 방송에 나온 맛집은 검증된 선택지지만 프로그램별로 흩어져 있어 한 번에 비교하기 어렵다.
- 목표: 출발 전 5분 안에 "1시간쯤 지나서 점심, 한식, 2만 원 이하" 같은 조건으로 경로 위 후보를 확정할 수 있어야 한다.

## 해결 방식 (핵심 기능)

1. **경로 위 시간 좌표.** 카카오모빌리티 Directions로 경로를 받고, 12개 방송 프로그램 약 3,400곳의 맛집 중 경로 반경 2km 안에 있는 곳을 "출발 후 N분 · 경로에서 X km"로 정렬해 지도와 목록에 함께 보여준다.
2. **AI 식사 플래너.** 자연어 한 문장으로 조건을 말하면 최대 3곳을 근거와 함께 추천한다. "30분 더 일찍", "더 저렴하게" 같은 후속 요청으로 조건을 이어서 수정할 수 있고, 지도와 추천 카드가 동시에 바뀐다.
3. **지도·목록 연동.** AI 추천만 지도에 표시하거나 경로 전체로 전환, 방송·업종 필터, 상세(메뉴·가격·출연 영상), 저장.
4. **검색 전 탐색.** 경로를 넣기 전에는 지도 영역 기준으로 전국 방송 맛집을 둘러볼 수 있다.

## AI 활용 방식

- **역할 분리.** LLM(DeepSeek Chat Completions, JSON Output)은 사용자 문장을 구조화 조건(업종·방송·메뉴 키워드·예산·시간대·정렬)으로 **해석만** 한다. 식당 선택, 순위, 근거 문장은 서버(Python)가 DB에 있는 메뉴·가격·방송 사실로 계산한다. 그래서 AI가 식당명이나 가격을 만들어내는 환각이 구조적으로 불가능하다.
- **신뢰성 장치.** Pydantic 스키마 검증, 프롬프트 인젝션 방어(사용자 입력은 데이터로만 취급), 확인할 수 없는 요청(주차·분위기·알레르기 등)은 "미확인 조건"으로 표시, 조건에 맞는 곳이 없으면 몰래 완화하지 않고 빈 결과를 돌려준다.
- **대화 맥락.** 전체 대화 원문 대신 직전의 구조화 조건만 모델에 전달해 토큰과 비용을 줄이고 결과를 재현 가능하게 유지한다. 좌표와 식당 데이터는 모델에 보내지 않는다.
- **운영 한도.** 동시 호출 4개, 경로당 20회, 45초 타임아웃, 오류 코드 분리(429/502/503/504/410).
- **데이터 검색에는 LLM을 쓰지 않는다.** 방송 태그처럼 정확 일치가 중요한 구조화 데이터라 벡터 검색 대신 SQL 인덱스 조회를 택했다. 판단 근거는 저장소 `docs/superpowers/specs/`의 설계 문서에 남겨 두었다.

## 사용한 AI 툴

- 서비스 런타임: DeepSeek Chat Completions API (JSON Output, non-thinking 모드)
- 제작 과정: Claude Code (Claude Sonnet 5 · Opus 5 · Fable 5.1). 설계 문서 → 구현 계획 → 구현 → 테스트의 스펙 주도 워크플로로 100개 이상 커밋을 AI 페어 프로그래밍으로 진행했다. 설계 문서와 계획은 `docs/`에 그대로 남아 있다.

## 데이터 출처 · 윤리 · 한계

- 맛집 데이터는 맛집여지도(matzipmap.com)의 공개 페이지에서 수집했다(프로그램, 이름, 주소, 좌표, 메뉴·가격). 요청 간 1초 딜레이와 연락처가 담긴 User-Agent를 사용해 서버 부하를 최소화했고, 서비스 안에서 원 출처를 명시한다.
- 정식 서비스 단계에서는 제휴 또는 자체 수집 DB로 전환할 계획이며, 이 리스크는 설계 문서에 기록해 두었다.
- 표시 시간은 경로상 통과 예상 시점이며 우회·정차 시간은 포함하지 않는다. 출발지 반경 안의 식당은 "출발 직후"로 표시한다. 가격은 메뉴 1개 기준이다.
- 사용자 입력 문장만 AI에 전달하고 위치 좌표·식당 데이터는 보내지 않는다. 로그인과 개인정보 수집이 없다.

## 확장 계획

- 대중교통·도보 경로와 출발 시각 입력을 받아 "도착 시각 기준" 추천
- 유튜브 맛집 채널 확대, 이미 운영 중인 건의함으로 방송 추가 요청 수집
- 다중 정차 코스(점심 + 카페) AI 플래너, 저장 목록 기반 개인화

## 데모 시나리오 (3분)

1. 출발지·목적지 입력 → 경로와 "출발 후 N분" 목록이 지도 위에 뜬다.
2. 결과가 뜨면 AI 입력창에 바로 커서가 놓인다. "한 시간쯤 뒤, 한식으로 2만 원 이하" → 3곳 추천, 근거, 적용 조건 칩.
3. "30분 더 일찍" → 지도와 추천이 동시에 바뀐다. 경로 전체 목록에서도 AI가 고른 곳은 "AI 추천" 배지로 구분된다.
4. 상세에서 메뉴·가격·출연 영상을 확인하고 저장한다.
