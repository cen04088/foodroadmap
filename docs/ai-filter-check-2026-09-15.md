# AI 조건 해석·필터 점검 (2026-09-15)

## 점검 방법

실제 배포 API에서 서울역→강릉역 경로를 한 번 조회하고 같은 경로에서 AI 요청 16개를 순차 실행했다. 추가 LLM 키를 사용하거나 배포 설정을 변경하지 않았다. 추천 ID·시간·업종·방송을 경로 응답과 대조하고, 추천 근거 메뉴의 가격을 확인했다. 공개 경로 API는 표시 메뉴 3개만 반환하므로 전체 메뉴 DB와의 완전한 대조는 수행하지 않았다.

## 정상 확인

- ‘한 시간쯤 뒤, 한식으로 2만 원 이하’: 시간 60분±30분, 한식, 메뉴 상한 20,000원으로 해석.
- ‘30분 더 일찍’: 목표 시간만 30분으로 바꾸고 업종과 예산 유지.
- ‘더 저렴하게’: 가격순 정렬로 변경, 시간과 예산 유지.
- ‘예산 제한 없이’와 ‘시간 상관없이’: 해당 조건만 해제.
- ‘국수 메뉴가 1만원 이하’: 국수 메뉴와 메뉴 가격 상한 모두 충족.
- ‘또간집에 나온 곳만’: 반환된 식당의 방송 태그 일치.
- 주차/조용한 분위기 요청: 미확인 항목으로 표시.
- 절대 시각(낮 12시)·네 명 총예산 3만원: 출발 후 시간/메뉴당 예산을 되물음.
- 출발 30~60분 범위 및 전체 조건 초기화 정상.

16회 모두 HTTP 200이었고 기계적 스키마·시간·가격 대조는 통과했으나, 아래 의미상 오류가 확인됐으므로 ‘16개 시나리오 모두 정상’으로 평가하면 안 된다. 음식 이름의 의미는 별도 수동 검토와 회귀 테스트로 확인했다.

## 발견한 오류와 로컬 수정

| 실제 관찰 | 원인 | 수정 |
|---|---|---|
| 기본 식사 추천의 `회 추가` | 추가 메뉴를 일부 이름으로만 제외 | 접미사/괄호 속 ‘추가’, 후식 표시를 판별 |
| 저렴한 순서에 `계란 600원`, `라면사리 1,000원`, `사리떡 2,000원` | 곁들임 메뉴 누락 | 명시적인 사리·단품 계란 표기를 제외. 메뉴 검색 때도 적용 |
| 해산물 제외에 `생굴(추가,계절메뉴)` | 해산물 범주에 굴 관련 이름 누락 | 생굴·석화·굴국밥 등 추가 |
| 회 요청에 `참치김밥`, `고등어구이`, `고등어김치찜` | ‘회’를 전체 해산물로 확장 | 회/횟집/사시미를 별도 범주로 분리. 단일 ‘회’의 무조건 부분 일치 방지 |
| 고기 제외에 순대국이 남음 | 일부 육류 메뉴만 등록 | 순대·닭·오리 등 명시적 이름 보완 |
| 생소한 ‘유니콘무지개돌솥밥’을 ‘돌솥밥’으로 축약 | 모델이 메뉴 일부를 미확인 속성으로 분리 | 특정 메뉴명 전체를 보존하도록 프롬프트 보완 |

존재하지 않는 메뉴 요청은 이번 경로에서 결과가 없었지만, 이름을 축약한 해석은 우연히 빈 결과가 됐을 뿐이므로 정상 해석으로 보지 않는다. 프롬프트 보완의 실제 모델 효과는 배포 후 재검증해야 한다.

## 검증 및 범위

실제 발견 사례를 반영한 21개 회귀 테스트를 추가했다. 수정 후 백엔드 전체 201개 테스트 통과. 음식 조건과 가격이 같은 메뉴에 적용되는지, 추가 메뉴가 가격순 순위를 왜곡하지 않는지, 명시적으로 추가 메뉴 자체를 검색하는 기존 동작은 유지되는지 검증했다.

변경은 로컬 상태이며 푸시/배포는 수행하지 않았다. 배포 후 기본 추천·가격순·해산물 제외·회 검색과 생소한 메뉴명 보존을 다시 확인해야 한다.

남는 한계: 음식 범주 검색은 명시적 이름 사전 기반이며 모든 식재료·조리법·인분 수를 판별하지 않는다. 단순히 ‘볶음밥’으로만 등록된 메뉴가 단독 식사인지 추가 주문인지 확정할 수 없고, 음식 제외를 알레르기·채식 안전 보장으로 사용할 수 없다.
